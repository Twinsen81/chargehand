# Decisions

This document records the resolved design decisions for chargehand. Each entry states the
**provisional** decision and its rationale. Every decision is reversible; the last column
says what changing it would involve. The full design is in [docs/DESIGN.md](docs/DESIGN.md).

| # | Decision | Provisional choice | Rationale | How to change |
| - | -------- | ------------------ | --------- | ------------- |
| 1 | Name and packaging | `chargehand` — PyPI package, import package, and console script | One name for the runner. The lease tool, banksman, is a separate tool with its own name (see 17). | Rename the package directory, `pyproject.toml` entries, and the config paths in one change. |
| 2 | License and contributions | Apache-2.0, DCO sign-off | Permissive with a patent grant; DCO avoids a CLA. | Relicensing needs every contributor's consent — decide before accepting outside contributions. |
| 3 | Runtime | Python 3.11+, standard library only | `tomllib`, `sqlite3`, `urllib`, and `argparse` cover the need. A tool that launches privileged agents should have the smallest possible supply chain and install friction. | Add a dependency only with a justification in the PR; keep test-only dependencies separate. |
| 4 | Agent backend | Claude Code first; runtimes are adapters | The runner depends on background sessions, their supervisor, and the machine-readable session list. No other agent CLI offers an equivalent today, so `claude` is the only runtime that ships and the default. It sits behind a runtime interface (launch, wake with a message, stop, observe session states, attach command, fork) with declared capabilities, and the tick and the CLI check capabilities, never the runtime's name. The test suite runs the tick on a second, fake runtime with fewer capabilities, so the interface does not collect Claude-only assumptions. | A second runtime is a new module: it implements the interface, declares its capabilities, and checks its own role-file keys. Each capability it lacks must be probed against the real agent first. |
| 5 | Platform | macOS first | launchd scheduling and the Keychain are assumed. | Linux needs a systemd user timer and a secret store; the core is platform-neutral. |
| 6 | Distribution | An installed tool plus one config file per repo — never copied scripts | Copies drift and never receive fixes. | n/a — this is the point of the project's shape. |
| 7 | Routing | Per assignee; no shared queue | Each runner uses its owner's tracker credentials and picks up only issues assigned to that person. Runners never compete, and every unattended run has a named owner. | A shared pool needs an atomic claim (for example a create-if-absent git ref) and stale-claim recovery. At that point it is a job queue; consider a dispatcher instead. |
| 8 | Trigger | Polling on a timer, not webhooks | No public endpoint, no tracker admin rights, works behind NAT. A few requests per tick is far below any rate limit. | A webhook receiver could kick a tick early; polling must remain as the fallback. |
| 9 | Trackers | Built-in `linear` and `github` adapters plus a `command` adapter | Four operations are enough: who am I, list by status, mark status, re-read. The `command` adapter lets anyone script another tracker without a plugin framework. | Add a built-in adapter when a tracker is common enough to deserve one. |
| 10 | Queue markers | Labels: `chargehand`, `chargehand-running`, `chargehand-blocked` (configurable) | Labels exist in every mainstream tracker and make the queue visible in ordinary tracker views. | Adapters may map statuses to something else (a custom field, a column). |
| 11 | Permission mode | `auto` by default; `bypassPermissions` is an explicit opt-in | Auto mode works unattended out of the box and falls back to a prompt, which the runner already surfaces as "blocked". The other modes either block on every command or need a hand-curated allowlist. | Set `permission_mode` per repo. |
| 12 | Launch prompt | Identifier and URL only — never issue text | The prompt is a trusted user message; issue text is attacker-controlled. The agent fetches the issue itself so the text arrives as a tool result. | Do not change without revisiting the threat model in `SECURITY.md`. |
| 13 | Control plane | A CLI on the machine that runs it. No server. | Nothing to expose, no token, no browser-borne attacks. It is a plain CLI, so SSH works if you want it, but nothing depends on that and reaching a machine remotely is the operating system's job. | An optional read-only, loopback-only status page may be added; it must never gain mutating endpoints. |
| 14 | Side effects | One writer: control commands record a request, the tick applies it | launchd runs one tick at a time, which serializes control actions with launches and reconciliation for free. | n/a — removing this reintroduces races. |
| 15 | Crash safety | Ledger first, idempotent steps, reconciliation on every tick | A crash or an ambiguous tracker write must never strand an issue or leave a session unsupervised. | n/a. |
| 16 | Concurrency | `max_concurrent` throttles launches; the memory bound is the lease tool's counted slots | Blocked runs must not hold launch slots or the queue stalls, and replies cannot be gated by the runner. Heavy work is what needs bounding, not sessions. | Tune `max_concurrent`, `max_open_workers`, and the lease tool's slot counts per machine. |
| 17 | Lease tool | An external tool, optional, that chargehand never calls. The repository's scripts take leases; chargehand keeps the properties a lease tool relies on (a worker's commands run below its own agent process, the branch names the work item, stopping a worker ends its process) and denies the tool's operator commands to agents | Sharing devices, emulators, and build slots between parallel runs is a separate product, with clients outside the runner. banksman finds the holder, ends the leases of an agent process that has ended, and reaps on its own, so a call from the runner added only a dependency on its output schema. A release by worktree could take a lease from another agent in the same worktree. | If the grace period after a stop is too slow, run a configured command when a worker stops, keyed by something that only that worker holds. |
| 18 | Repo configuration | A single `.chargehand.toml` at the repository root | Discoverable and tool-named; holds the prompt, setup script, base branch, and permission mode. Machine-specific settings stay out of the repo. | The path is a constant in one place. |
